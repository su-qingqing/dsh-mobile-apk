**那 731MB 不是交接库，是"会话日志全文检索库"——它存的是"过去说过的话"，而交接要的是"现在在办什么"。**

# 一、这 731MB 到底是什么

## 1.1 真实 DDL（逐字取自 `sqlite_master`，`probe2.out:25-60`）

```
[table] meta(sid text primary key, proj text, file text, size integer,
             mtime integer, t0 integer, t1 integer, nrec integer, built_at integer)
[table] raw(id integer primary key autoincrement, sid text, seq integer,
             time integer, kind text, role text, text text)
[index] raw_sid on raw(sid)
[table] ft            -- CREATE VIRTUAL TABLE ft using fts5(bg, tokenize='unicode61')
[table] ft_content(id INTEGER PRIMARY KEY, c0)          ← FTS5 影子表
[table] ft_data(id INTEGER PRIMARY KEY, block BLOB)     ← FTS5 影子表
[table] ft_docsize(id INTEGER PRIMARY KEY, sz BLOB)     ← FTS5 影子表
[table] ft_idx(segid, term, pgno, PRIMARY KEY(segid,term)) WITHOUT ROWID
[table] ft_config(k PRIMARY KEY, v) WITHOUT ROWID
```

没有视图、没有触发器、没有其它索引。**总共 8 张表，11 个对象。**

## 1.2 行数与字段语义

| 表 | 行数 | 语义 |
|---|---:|---|
| `meta` | **336** | 一个会话窗口一行。`t0/t1`=窗内首末记录时刻，`nrec`=记录数，`built_at`=**该窗被收进索引的时刻**，`file`=zstd 日志绝对路径 |
| `raw` | **127,376** | 一条消息一行。`kind`∈{call 68,234 / assistant 54,882 / user 4,051 / todo 209}，`role`∈{tool / assistant / user / note}，`text`=正文（**硬截断 20,000 字符**） |
| `ft` 及其影子表 | 127,376 | FTS5 倒排。`ft_content.c0`=**单字切分后的 token 串**，`ft_data`=倒排块，`ft_idx`=词典 |

字段语义关键点：
- **`kind='user'` 才是"老板原话"**（4,051 条），`kind='call'` 是工具调用（占 53.6%），`kind='assistant'` 是她自己的正文。
- `raw.text` 平均 1,275 B、最长 20,000 B；**152 条撞上 20,000 上限被截断**（`probe3.out:56`），是已知的有损点。
- `meta.built_at` 是**唯一的"收录时刻"**，与 `t1`（窗内末次活动）之差就是**索引滞后**。

## 1.3 谁在写、什么时候写

**唯一的写入方：`工具/跨窗/接续.mjs`。** 全工作区 `.mjs` 里只有它和 `追条文来源.mjs` 打开这个库（`grep -rln '跨窗/接续'` 结果集，见证据 E6）。

| 位置 | 干什么 |
|---|---|
| `接续.mjs:110-118` `openDb()` | 建表（就是上面那套 DDL） |
| `接续.mjs:120-167` `build()` | **扫描 336 个 zstd 会话日志 → 解帧 → 逐条 INSERT 进 `raw` + `ft`** |
| `接续.mjs:130` | 增量判据：`size` 与 `mtime` 都没变 ⇒ 跳过 |
| `接续.mjs:154` | 变了就 **先 `delete from ft` + `delete from raw`（整窗全删），再整窗全插** |
| `接续.mjs:158` | `insFt.run(rowid, toks(text).join(' '))` —— **中文一字一 token，用空格连** |
| `接续.mjs:245-249` | 距上次收录 >10 分钟就自动增量刷一遍 |

**写入时机 = 有人手工跑 `node 工具/跨窗/接续.mjs`（含 `工具/开工/库.mjs:769` 间接调用）。**
**与打烊/抽针/出卡/开窗/进场门 —— 一次关系都没有**（见 §2.2 的证据）。

## 1.4 731MB 是异常膨胀吗？是。三重叠加

### 体积实测（`dbstat`，权威口径，`probe3.out:1-36`）

| 对象 | MiB | 占比 |
|---|---:|---:|
| **raw**（原文叶页） | 177.2 | 25.5% |
| **raw**（溢出页） | 106.4 | 15.3% |
| **raw 小计** | **284.1** | **40.9%** |
| **ft_content**（FTS 正文副本） | **223.3** | **32.2%** |
| **ft_data**（FTS 倒排块） | **178.0** | **25.6%** |
| raw_sid / ft_docsize / ft_idx / meta | 8.9 | 1.3% |
| **合计** | **694.4** | 100% |

**实际文本只有 154.9 MiB（`raw.text` 字节和），库是 694.4 MiB ⇒ 4.50 倍。**

### 膨胀成因① —— `ft_content` 223 MiB 是 100% 纯冗余

`接续.mjs:116` 建的是 `fts5(bg)`，**没有 `content=''`、也没有 external content**，FTS5 因此把被索引内容**整份再存一遍**。而存的是 `toks()` 的单字串，`ft_content` payload = 143.6 MB（`probe2.out:87`），落到 223.3 MiB。
**这 223 MiB 里没有任何信息是 `raw.text` 算不出来的。**

### 膨胀成因② —— 单字切分把倒排表撑爆：`ft_data` 178 MiB

`接续.mjs:40-49` 的 `toks()` 把每个汉字切成独立 token。后果：

- 词典只有 **7,853 个不同 term**（`probe3.out:61`）—— 汉字集合就这么大
- 但总 token 数 ≈ 5,000 万级 ⇒ **每个 term 挂一条百万量级的倒排链**
- 倒排块 47,468 个 × 平均 3,871 B = 175.2 MiB（`probe3.out:39`）
- 段结构**从未压实**：`ft_idx` 有 segid 1,2,3,4,5,6,7,8,9,14 共 10 段，词条数 3058/2437/908/1062/1012/**4302**/1/191/36/170（`probe4.out:49-58`）—— 典型的"只追加、不合并"形状

> 而这段代码自己承认（`接续.mjs:204-216`）：召回后要用 `String(text).includes(kw)` **精确包含**再滤一遍，因为单字会把噪声全捞上来。
> 也就是说：**倒排表只负责"召回"，精确性靠线性扫描兜住 ⇒ 178 MiB 买回来的是一个"大概范围"的过滤器。**

### 膨胀成因③ —— 89% 的行是垃圾，`auto_vacuum=0` 且从不 VACUUM

- `raw` 现在 **127,376 行**，`max(rowid)` 却是 **1,183,915**（`probe2.out:70`）⇒ 累计插入过 118 万行，**删掉 1,056,539 行 = 89.3%**
- `PRAGMA auto_vacuum = 0`、`journal_mode = delete`、freelist 只有 759 页（3 MB）（`probe2.out:10-22`）
- `raw` 叶页 185.8 MiB 里只用 146.0 MiB，**21.4% 是空洞**（`probe3.out:3`）
- 全文件搜 `optimize|vacuum|VACUUM|merge` 命中 **0 处**（证据 E7）⇒ **FTS5 段从不合并、文件从不瘦身**

### 膨胀时间线（实测）

| 时点 | 大小 |
|---|---|
| 2026-09-26 10:06 | **190.3 MiB**（`tmp/index.db.bak-0926`，199,573,504 B） |
| 2026-10-26 21:13 | **697.3 MiB**（731,205,632 B） |

一个月 **3.66 倍**。按 `built_at` 直方图（`probe3.out:112-141`），10-12 单日重扫 40 窗、10-13 重扫 54 窗 —— 每次重扫都是"整窗全删 + 整窗全插"。

### 附：整份数据盘上早已有一份

`meta.size` 求和 = **555.1 MiB zstd**（336 个会话日志，盘上现存）。
**555 MiB 真源 + 697 MiB 明文副本 + 索引 = 1.25 GB 存同一份东西，而副本是 `zstd -dc` 一条命令就能再生的。**

# 二、它有没有解决交接问题？没有。逐条对账

## 2.1 结构性答案：这个库里**没有"状态"这个概念**

对 8 张表逐条查（证据 E8，`probe4.out:71-84`）：

| 要回答的问题 | 库里的对象 | 结果 |
|---|---|---|
| 本窗现在在办什么 | `在办` 表 | ❌ `no such table: 在办` |
| 上一窗留下的针 | `针` / `needle` 表 | ❌ 无 |
| 上一窗留下的卡 | `卡` / `card` 表 | ❌ 无 |
| 交接单 | `handoff` 表 | ❌ 无 |
| 这条状态过没过期 | `meta`/`raw` 里的 expire/ttl/stale 字段 | ❌ 一个都没有 |

与交接概念（针·卡·交接·在办·状态·目标·令·门·开窗·打烊）匹配的对象数 = **0**（`probe3.out:155`）。
它只能回答"这话谁在哪个窗说过"——**是档案馆，不是驾驶舱。**

## 2.4 对账⑧「过期状态当现令」—— 库里没有过期字段，读者也不查

- `状态行.json` 里其实**有** `"as_of_seq": "2026-10-25T04:34:12.859Z"`（第 5 行）
- 但 `raw`/`meta` **没有任何 expire/ttl/state 字段**（`probe4.out:80-84`）
- 而 ffbd4d3f 读的是 `状态行.json` 的**内容**，不是它的时间戳 ⇒ 时间戳写在那儿，没人看

**病灶不是"缺字段"，是"有三个真源且都不带强制 TTL"。**

## 2.5 它不是没用，是用错了地方

`工具/开工/库.mjs:769` 会跑 `工具/跨窗/接续.mjs`，`工具/开工/找.mjs:210` 会用 `接续.mjs 找`。
⇒ 它确实在被用，**但只当"翻旧账的搜索框"用**——找"这话说过没有"。
而交接要的是"**现在**在办什么 / 上一窗交到哪儿 / 这条还作不作数"，这三问它一问都答不了。

## 2.6 索引本身是新鲜的（这条要给她记功）

滞后实测（`probe4.out:133-146`）：最近 12 窗里 7 窗滞后 ≤1 分钟，最差 656 分钟（d33317a9、1cfe9217）。
**收录侧没问题，读的人/存的模型有问题。**

# 三、v52 跨窗交接库设计

## 3.1 三条定规（先立规矩，再建表）

1. **一个真源，三份渲染。** 交接库是唯一可写真源；`状态行.json` / `交接单_*.md` / `台账/在办.md` 全部降级为**只读渲染产物**，谁也不许手写。
2. **原文不进库。** 会话日志（555 MiB zstd）是真源，库里只存指针（`sid`+`seq`）。检索索引做成**可丢弃、一条命令可重建**的副产品，且**与交接库物理分文件**。
3. **每条都带 TTL。** 没有 `expires_at` 的行不许进 `doing`/`card_row`；读的人**必须先判过期再当现令**。

## 3.2 物理布局

```
$DSH_HOME/state/跨窗/handoff.db     ← 交接库（真源，小，天天写）
$DSH_HOME/state/跨窗/index.db        ← 检索库（可丢弃，contentless，只读+批量重建）
（旧 731MB 那个：迁移完直接删，它 100% 可再生）
```

## 3.3 建表 SQL（可直接执行）

存为 `工具/跨窗/建库.sql`，用 `node` 的 `DatabaseSync.exec()` 或 `sqlite3` 跑。

```sql
-- ══════════════════════════════════════════════════════════════════
-- 跨窗交接库 v52 · 真源
-- 跑法（node）：
--   const db=new DatabaseSync(DB); db.exec(SQL);   // 逐条 exec，PRAGMA 先跑
-- 注意：auto_vacuum 必须在建任何表之前设，否则不生效
-- ══════════════════════════════════════════════════════════════════
PRAGMA journal_mode = WAL;          -- 并发读写不互相锁死（现在是 delete，写会锁库）
PRAGMA synchronous  = NORMAL;
PRAGMA auto_vacuum  = INCREMENTAL;  -- ★ 治 731MB 的第③斧：删了能还空间
PRAGMA foreign_keys = ON;
PRAGMA busy_timeout = 5000;
PRAGMA user_version = 52;           -- ★ 老库是 0，一眼能分新旧

-- ── 1. 窗（接替 meta，加"类型/状态/★三级"）────────────────────────
CREATE TABLE win(
  sid         TEXT PRIMARY KEY,                 -- session-xxxxxxxx
  proj        TEXT NOT NULL DEFAULT '',         -- 工作区
  opened_at   INTEGER NOT NULL,                 -- 开窗时刻 ms
  closed_at   INTEGER,                          -- 打烊时刻 ms；NULL = 在跑
  kind        TEXT NOT NULL DEFAULT '干活'
              CHECK(kind IN ('干活','调研','聊天','救场','关系')),  -- 设计v2 §六
  title       TEXT NOT NULL DEFAULT '',
  state       TEXT NOT NULL DEFAULT '在跑'
              CHECK(state IN ('在跑','已结','废')),
  log_file    TEXT NOT NULL DEFAULT '',         -- ← 真源指针（不存正文）
  log_size    INTEGER NOT NULL DEFAULT 0,
  log_mtime   INTEGER NOT NULL DEFAULT 0,
  nrec        INTEGER NOT NULL DEFAULT 0,
  nstar_think INTEGER NOT NULL DEFAULT -1,      -- ★三级存活链（设计v2 §五）
  nstar_reply INTEGER NOT NULL DEFAULT -1,      -- -1 = 未测，绝不冒充 0
  nstar_card  INTEGER NOT NULL DEFAULT -1,
  built_at    INTEGER NOT NULL
);
CREATE INDEX win_closed ON win(closed_at DESC);
CREATE INDEX win_state  ON win(state, opened_at DESC);
CREATE INDEX win_kind   ON win(kind, closed_at DESC);

-- ── 2. 针（老板一句原话，机械抽、逐字、幂等）───────────────────────
CREATE TABLE needle(
  id      INTEGER PRIMARY KEY,
  sid     TEXT NOT NULL REFERENCES win(sid) ON DELETE CASCADE,
  seq     INTEGER NOT NULL,               -- 日志内序号：回真源用
  at      INTEGER NOT NULL,                -- 他说这话的时刻
  kind    TEXT NOT NULL
          CHECK(kind IN ('纠正','命令','环境','情境','普通')),
  text    TEXT NOT NULL,                   -- 逐字原文，不转述
  used_by INTEGER                          -- 被哪条 card_row 用了；NULL=还没用
);
CREATE UNIQUE INDEX needle_uniq ON needle(sid, seq);   -- ★ 抽针幂等，重复跑不生第二根
CREATE INDEX needle_sid  ON needle(sid, seq);
CREATE INDEX needle_kind ON needle(kind, at DESC);

-- ── 3. 卡（换窗卡，三态；只有 [已审] 能进下一窗）────────────────────
CREATE TABLE card(
  id         INTEGER PRIMARY KEY,
  sid        TEXT NOT NULL UNIQUE REFERENCES win(sid) ON DELETE CASCADE,
  state      TEXT NOT NULL DEFAULT '草稿'
             CHECK(state IN ('草稿','待审','已审','作废')),
  mine_id    TEXT,                        -- 雷号 RQ-YYMMDD-XXXX（别处搜不到）
  created_at INTEGER NOT NULL,
  audited_at INTEGER,                     -- ★ 只有 [已审] 才非空
  md_path    TEXT                         -- 镜像 .md，给人看；库才是机器真源
);
CREATE INDEX card_state ON card(state, created_at DESC);

-- ── 4. 卡行（卡的每一格；★ 第③级的落点；带 TTL）────────────────────
CREATE TABLE card_row(
  id         INTEGER PRIMARY KEY,
  card_id    INTEGER NOT NULL REFERENCES card(id) ON DELETE CASCADE,
  slot       TEXT NOT NULL
             CHECK(slot IN ('雷','零损失区','默契','感情','死路','原话','成果','指路')),
  kind       TEXT NOT NULL,               -- 决定/禁止/被否/做法/结果/教训/已完成/未完成/卡在谁
  body       TEXT NOT NULL,
  src_needle INTEGER REFERENCES needle(id),   -- ★ 能追到针（设计v2 验收#5）
  verified   INTEGER NOT NULL DEFAULT 0,      -- 0=未核实 1=机器核过
  nstar      INTEGER NOT NULL DEFAULT 0,      -- 本行 ★ 个数 = 第③级
  state      TEXT NOT NULL DEFAULT '活'
             CHECK(state IN ('活','过期','被否')),
  expires_at INTEGER,                          -- ★ 过期时刻：治"过期状态当现令"
  created_at INTEGER NOT NULL
);
CREATE INDEX cardrow_card ON card_row(card_id, slot);
CREATE INDEX cardrow_live ON card_row(state, expires_at);
CREATE INDEX cardrow_need ON card_row(src_needle);

-- ── 5. 在办（★ 三套口径收敛成这一张）──────────────────────────────
CREATE TABLE doing(
  id         INTEGER PRIMARY KEY,
  goal_id    TEXT,                        -- goal-54577121（引擎侧 id，可空）
  title      TEXT NOT NULL,
  body       TEXT NOT NULL DEFAULT '',
  step       TEXT NOT NULL DEFAULT '',    -- 到哪一步
  next       TEXT NOT NULL DEFAULT '',    -- 下一步
  ball       TEXT NOT NULL DEFAULT '我'
             CHECK(ball IN ('我','老板','电脑侧','等')),   -- ★ 球在谁那儿
  state      TEXT NOT NULL DEFAULT '在办'
             CHECK(state IN ('在办','待审','挂起','已结')),
  owner_sid  TEXT REFERENCES win(sid),    -- 哪一窗在办
  opened_at  INTEGER NOT NULL,
  updated_at INTEGER NOT NULL,
  expires_at INTEGER,                     -- ★ 没有 TTL 的行不许进
  src        TEXT NOT NULL DEFAULT ''     -- 从哪份老文件迁来的（取证用）
);
CREATE INDEX doing_state ON doing(state, updated_at DESC);
CREATE INDEX doing_exp   ON doing(expires_at);
CREATE UNIQUE INDEX doing_goal ON doing(goal_id) WHERE goal_id IS NOT NULL;

-- ── 6. 交接单（保留她已有的原型，补 TTL 与归属）─────────────────────
CREATE TABLE handoff(
  key        TEXT PRIMARY KEY,
  title      TEXT NOT NULL,
  state      TEXT NOT NULL,
  by         TEXT,
  at         TEXT NOT NULL,
  note       TEXT,
  hist       TEXT NOT NULL DEFAULT '',
  spec       TEXT,
  sid        TEXT REFERENCES win(sid),    -- 新增：归属窗
  expires_at INTEGER                      -- 新增：TTL
);
CREATE INDEX handoff_sid ON handoff(sid);

-- ── 7. 体检账（自检结果落盘，可被别的门读）─────────────────────────
CREATE TABLE audit(
  id     INTEGER PRIMARY KEY,
  at     INTEGER NOT NULL,
  who    TEXT NOT NULL,                  -- 打烊/抽针/出卡/开窗/进场/体检
  item   TEXT NOT NULL,
  ok     INTEGER NOT NULL,                -- 1/0
  detail TEXT NOT NULL DEFAULT ''
);
CREATE INDEX audit_at   ON audit(at DESC);
CREATE INDEX audit_item ON audit(item, at DESC);

-- ── 8. 唯一在办口径（★ 三套渲染都从这个视图出）─────────────────────
CREATE VIEW v_doing AS
SELECT d.id, d.title, d.step, d.next, d.ball, d.state, d.goal_id,
       (CAST(strftime('%s','now') AS INTEGER)*1000 - d.updated_at)/86400000 AS 陈旧天,
       CASE WHEN d.expires_at IS NOT NULL
             AND d.expires_at < CAST(strftime('%s','now') AS INTEGER)*1000
            THEN 1 ELSE 0 END AS 已过期,
       CASE WHEN d.expires_at IS NULL THEN 1 ELSE 0 END AS 无TTL
FROM doing d;

-- ── 9. 上一窗可接的卡（只有 [已审] 出得来）──────────────────────────
CREATE VIEW v_prev_card AS
SELECT c.id, c.sid, c.mine_id, c.audited_at, w.closed_at, w.kind
FROM card c JOIN win w ON w.sid=c.sid
WHERE c.state='已审'
ORDER BY w.closed_at DESC;
```

## 4.5 一个必须记的坑（不是现在的 bug，是明天的）

`工具/跨窗/追条文来源.mjs:13` 用的是 `process.env.HOME + '/.dsh/state/跨窗/index.db'`，而 `接续.mjs:21` 用的是 `DSH_HOME + '/state/跨窗/index.db'`。
两条路径拼法不同，**只要 `process.env.HOME` 在 Termux/干净房间里被设成别处，`DatabaseSync(DB)` 会在新路径静默建一个空库**（它没有 `readOnly: true`）。

**v52 修法：全系统只许用 `DSH_HOME`（或统一常量），且所有只读场合一律 `new DatabaseSync(DB, { readOnly: true })`（现在 6 处 `new DatabaseSync(DB)` 都没带）。**
