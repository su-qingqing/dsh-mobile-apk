# 二、三条根因（六问归三）

### 根因 A · **注入面没有预算宿主，且计量尺子错**（对应问题 1）

- 十来源各写各的（`注入面.mjs:4-9`），`agent-instructions maxBytes:65536`（`cordis.patch.yml:409`）是**唯一的**天花板，但它只管"截不截"，不管"谁该被截"。
- 真正的大头是**压缩摘要每轮重发 24,041 字**（57.6%）与**工具定义 6.9 万字符/轮**（`注入面.mjs:107`），而两只都不在任何租限单上。
- 预算仪器把 `极限万` 写死 30（`上下文账.mjs:13`），真实线 80 万 ⇒ **越线之后报警恒红** ⇒ 与她造过的所有"假红"同命运（`神经/上下文门.mjs:14-15` 已经痛斥过告警/故障 rc 混用）。
- **`注入账` 这个数自己会过期**（`每轮必读.json:10` 那条自陈）——预算表居然是最没 TTL 的东西。

### 根因 B · **"有库、有口径、有命令"，但没有调用方**（对应问题 2、3）

同一形状犯了三次：

| 资产 | 状态 | 调用方数量 |
|---|---|---|
| 长期记忆快照 | 首轮一次 + `hitTopK=2`（`index.js:5242/2512/4594`） | ✅ 有（但配额 2 条） |
| `工具/记忆/负知识.mjs` 检索口 | 写好 65 行、退出码齐全 | **0**（只有把它印出来的 3 处文本） |
| 73 条负知识机编件 | 编译完成并在 `_素材` 里自陈"只是素材" | **0** |
| `工具/交接/针.mjs` / `出卡.mjs` | 造好挂在墙上 | **0**（02 号 E12） |
| `台账/接续/状态行.json` 的时间戳 | schema 里有 `as_of_seq` | **0**（读者只看内容） |

**形状是统一的：她擅长造"判断很准的件"，不擅长造"必然被拉的那根绳"。** 所以本文的每张格斗都必须写成"谁在第几步必须跑它"，而不是"将来要去看它"。

### 根因 C · **同一条通道、没有来源戳、没有 TTL**（对应问题 4、5、6）

- 老板原话、长期记忆、pins、runtime-context、技能目录，**全在同一个 user 通道**里进引擎（`签收.mjs:121` 自己列了通道名）。
- 引擎侧的 `meta.kind`（`initial/reinjection/hit`，`index.js:4494`）**从不出现在正文里** ⇒ 模型不可见。
- 状态有时间戳但**没有 `expires_at`**，失效条件写的是人话 ⇒ 机器判不了 ⇒ 过期卡继续当面令。
- 压缩同理：压缩是"把对话框删掉"，它**不认识的身份的制作 copies**。

# 三、上下文预算模型

## 3.1 三条建模公理

1. **按"占用窗口的量"分账，不按"来源"分账。** 一块内容进了上下文，它就占地方，不管它是从哪来的。
2. **摊销单位=字×存活步数。** 一次性写进对话但在对话里活到最后的内容 > 每步重发但很小的内容。这与她已确立的口径一致（`上下文账.mjs:5`："成本 ≈ 单条字节 × 它之后的步数"）。
3. **总窗 80 万不是可用额度。** 要先扣掉**永远不能动的**（常驻＋思考输出＋安全垫），剩下的才是"工作区余额"，这才是所有门该量的数。

# 七、TTL / 新鲜度语义（治疗"过期当现令"）

## 7.1 一个字段 + 一条规则

```
任何"会被当成现令读"的行，必须有 expires_at（Unix ms）。没有 ⇒ 不许进 doing/card_row/负知识条目，且 v_doing 报无TTL=1（02 §4.2 #10 已有）。
读者纪律：先判新鲜，再读内容；过期 ⇒ 用来做考古，不用来干活。
```

## 7.2 默认值（按"容不容易过期"分三档）

| 类 | TTL | 举例 | 过期后怎么办 |
|---|---|---|---|
| **老板原话/令** | **永不过期**（`expires_at = NULL`，但必须由 ⚠ `失效条件` 显式推翻） | `内核/全局要则.md:447` "我从来没有跟你说过提示字节不许长吧" | 只能被另一句老板原话推翻；脚本不许自动过期 |
| **状态行 / 在办 / 卡点** | **72 小时**（陈旧报红线 3 天，02 §4.2 #13 同口径）；卡点更短，= **24 小时** | `状态行.json`、`v_doing` | 过期 ⇒ 转到 `[等数据]` 且报"本窗无未过期状态"（§4.1 step 1） |
| **非老板原话的注入块（记忆快照/pins/运行时）** | **60 分钟**（沿用她 0923 定的冷却常量，不必新造数） | meow 快照、`hitTopK` 命中 | 过期后不许再自动重复注入；要用就靠 §5 的检索重新召回 |

## 7.3 把自然语言"失效条件"机器化（解开 `状态行.json` 的死结）

现状 `已定[].失效条件` 是 `"老板说「★回来」"`——人读得懂、机器判不了。改法：**保留原句，旁边补一个可求值表达式**：

```jsonc
{ "id":"D-1", "决定":"★退役：考试=从坑账随机抽题",
  "失效条件_原文":"老板说「★回来」",                       // 人看，不许删
  "失效条件": { "kind":"老板新令匹配", "pattern":"★回来|考试.*回来" },  // 机器判
  "expires_at": null }                                      // 老板层级 ⇒ 不自行过期
```
四项 `kind` 白名单（**超过这四种不许写**，否则机器注定判不了）：
`老板新令匹配` / `命令现跑rc==0` / `文件指纹变化` / `时间到了`。

- `神经/连续性.mjs:95-101` `新鲜()`：`at >= 本轮开于` —— **这就是 TTL 的一个实例**，只是只用于钥匙 `1·进场`。把它抽成 `工具/神经/新鲜度.mjs`，全系统共用一套。
