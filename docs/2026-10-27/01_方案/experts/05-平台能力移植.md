### 1.2 先移植这 3 个，为什么

#### 🥇 第 1 · 三层记忆（MEMORY.md 索引分层）

**为什么最对症**：她 6 个痛点里 4 个是同一条根因的不同症状——**记忆以"整块塞进注入面"的形态存在**。

- 上下文 68%（`CONTEXT.md:86`）→ 03 实测压缩摘要 24,041 字/轮（57.6%）+ 记忆块，记忆是 R0/R2 的大头（03 §3.3/§3.5）
- 记忆拿不回来 → `reinject:false` 吃掉（`台账/在办.md:228`）；`hitTopK` 默认 2 且**生产配置从没写过这项**（`台账/在办.md:352`，真源 `meow-memory/lib/index.js:2953`）⇒ 等于"只靠 2 条关键词命中"
- 过期状态当现令（`CONTEXT.md:82`）→ 库里没有过期语义（02 §2.4）
- 老板话 vs 注入（`CONTEXT.md:79`）→ 同一条通道、无来源戳（03 §6）

**分层把"检索"这件事绕过去了**，这才是关键。她自己已经把这句话写下来了：

> "它不是把检索做得更准，它是让**大部分记忆根本不需要被检索**。" —— `调研/跨窗交接/逐家精读-补充A.md:114`
> "既砍注入，又绕开了我们那个烂检索。" —— 同文件 `:199`

**为什么排第 1**：① 她已定案（`:234`："两条都能立刻落，且不需要模型能力"）；② 不改检索算法、不动引擎、不改插件，**纯文件布局**；③ 是第 2、3 项的地基（技能索引、子代理派活单都要引用记忆层的路径）。

#### 🥈 第 2 · Skills（SKILL.md 按需加载）

**为什么对症**：

- **上下文 68%**：03 §3.3 实测工具定义 **约 6.9 万字符/轮**（`注入面.mjs:107`），是唯一能一次省出 3 万多字的单点。技能目录 description 也吃 5.8%（≈2,421 字/轮）。
- **在跑旧货**（`CONTEXT.md:75`）：根因之一是**工具面全量常驻 ⇒ 改一件要攒重启批次 ⇒ 攒批期间跑的就是旧货**（`台账/在办.md:228` 现攒 6 件）。SKILL.md 正文在 sdcard 真源、按需读取 ⇒ **改完立刻生效，不需要重启**。

**为什么排第 2 而不是第 1**：引擎已原生支持（F1），落地成本比记忆层还低；但它**依赖记忆层给路径**（技能正文要指到记忆/经验的哪个文件），且它省下来的字节需要 03 的预算表来裁决"省下的配额给谁"——所以顺序上让记忆层先定框架。

**但要卡 03 的额度**：03 §3.3 给技能目录 description 的上限是 **≤1,500 字**。按每条 description ≤80 字算 = **≤18 条常驻**。她有 20 个内核件 + 120 个一级件 ⇒ **不能全都进技能索引**，必须分级（见 §3.3）。

#### 🥉 第 3 · 子代理并行 + 契约化输出 + 主代理审核

**为什么对症**：`32% 全量没做成 / 最近一周 45% 没做成`（`CONTEXT.md:86`），且 **332 窗全靠她自己一窗一窗跑**。她的外部核已经是"把活派出去"的形态，但：

- **串行**：`跨模型核.mjs:88` 是 `for (const id of 名单)`，单家超时 300s ⇒ 5 家最坏 25 分钟，且一家慢就全队等
- **无契约**：产物是 `答卷_<模型>.md` 自由文本（`:99-100`），没有机器可判字段 ⇒ 无法自动审核
- **无审核**：`汇总.json` 只记"状态/秒/字数"（`:102`），没有"采纳/驳回"这一步

**为什么排第 3**：它是**收益最大但风险也最大**的一项——一旦并发不安全，会撞上她已经修过两次的并发病（锁.mjs 头部注释：老板 1007 夜令"先修并发五处裸奔"；1013 收口的世代号）。必须等记忆层（给材料路径）和技能层（给能力边界）落定后再上。

### 1.3 明确不要移植的（硬搬会水土不服）

| 机制 | 不移植的理由（带证据） | 替代形态 |
|---|---|---|
| **automation 定时任务（RRULE/once/recurring）** ⭐最不该移 | ① **Android 没有可靠常驻**：应用进程随时被杀、Doze 休眠、Termux 无 cron 守护；② 全机 grep 无 `cron/定时/周期` 调度器（唯一命中是"复核周期"这类**字段**，不是调度器，`神经/出口账.mjs:47`）；③ **最致命**：它会长成第 120 个"门是摆设"——`CONTEXT.md:77` 已确诊"119 门只有 8 处真拦"。一个到点跑不起来的定时任务，比没有更坏：她会以为它跑了 | **事件触发**：挂 `压缩发生了` / `第 N 步` / `开窗` / `换窗` 四个必然事件。她自己已经写出这条判据——`逐家精读-补充A.md`："dreaming 的触发条件：按『完成 N 步』或『上下文被压缩时』跑，不是靠人喊……换窗前的整理，应该由『压缩发生了』来触发，而不是由老板记得说『打烊』" |

### 3.3 SKILL.md 字段（对齐引擎的 frontmatter 解析器）

引擎的解析器是 `vendor/dshmarketplace-plugin/lib/index.js:8` 里的 `Z()`：**只认 `^---\n...\n---\n` 之间的 `key: value` 行，不支持嵌套 YAML**。所以字段只能是一层 `k: v`。

```markdown

### 3.5 最小实现：`工具/技能/装技能.mjs`

```js
#!/usr/bin/env node
// 装技能 —— 把 sdcard 真源装进 $B/skills/，开窗时校验漂移
// 挂点：工具/开工/开窗.mjs（必然时刻，不是靠自觉 —— 03 §4.1 T0）
import fs from 'node:fs'; import path from 'node:path'
import { 带锁, 原子写 } from '../../神经/锁.mjs'
const 源 = '/storage/emulated/0/3/工具/技能'
const 的 = process.env.DSH_HOME + '/.dsh/skills'
const 账 = '/storage/emulated/0/3/工具/技能/_装机账.json'

const 扫 = 根 => fs.readdirSync(根, {withFileTypes:true})
  .filter(d => d.isDirectory() && !d.name.startsWith('_'))
  .map(d => path.join(根, d.name, 'SKILL.md')).filter(p => fs.existsSync(p))

function 装() {
  return 带锁('装技能', () => {
    const 报 = []
    for (const p of 扫(源)) {
      const 名 = path.basename(path.dirname(p))
      const 文 = fs.readFileSync(p, 'utf8')
      // 硬判据：frontmatter 必须有 name+description，缺一个就拒绝装机（不许静默）
      const m = /^---\r?\n([\s\S]*?)\r?\n---/.exec(文)
      const meta = {}; if (m) for (const l of m[1].split(/\r?\n/)) { const i = l.indexOf(':'); if (i>0) meta[l.slice(0,i).trim()] = l.slice(i+1).trim() }
      if (!meta.name || !meta.description) { 报.push({名, 状态:'拒装', 因:'缺 name 或 description'}); continue }
      if (meta.description.length > 80) { 报.push({名, 状态:'拒装', 因:'description '+meta.description.length+' 字 > 80'}); continue }
      const 目标 = path.join(的, 名, 'SKILL.md')
      fs.mkdirSync(path.dirname(目标), {recursive:true})
      const 旧 = fs.existsSync(目标) ? fs.readFileSync(目标,'utf8') : null
      if (旧 !== 文) 原子写(目标, 文)
      报.push({名, 状态: 旧===文 ? '未变' : '已装', sha: 摘要(文)})
    }
    原子写(账, JSON.stringify({at:new Date().toISOString(), 报}, null, 1))
    return 报
  }, { 等毫秒: 8000 })
}
const 摘要 = s => require('node:crypto').createHash('sha256').update(s).digest('hex').slice(0,12)
// CLI: node 装技能.mjs 装 | 查
```

**漂移自检（挂 01 的机制）**：`装技能.mjs 查` 比对 `_装机账.json` 的 sha 与 `$B/skills/` 实际内容；不一致 ⇒ 报"技能漂移，正在跑旧货"，与 01 §5 的 buildId 漂移自检同一张报表。

### 4.2 能不能起多个 node 子进程 / 多窗并发？

**能起多子进程，且已经实测过。** 证据：`神经/锁.mjs` 的自测**真跑两个 node 子进程争同一把锁**，并断言"两段临界区不重叠"（`锁.mjs` 自测真态一，含 `spawn(NODE, [我,'自测','抢',…])` 两进程 + 共享账本 `_锁/自测-争抢.jsonl`）。`工具/开工/库.mjs:1095` 也已有 `spawn(..., {detached:true, stdio:'ignore'}).unref()` 的后台子进程先例。

**三个必须知道的坑（都写在她的代码注释里）：**

1. **不能用 `process.execPath`** —— 平板上它指向 `linker64`，spawn 会报 `bad ELF magic`（`锁.mjs` 注释："本机实测（1007 夜）"）。必须给真 node 路径：
   `$F/files/usr/bin/node`，或 `process.env.DSH_NODE`。现成写法见 `锁.mjs` 的 `找node()` 与 `库.mjs:553`。
2. **`DSH_SESSION_ID` 在引擎进程里读不到** ⇒ 会退化成同一个 `'未知窗'` ⇒ **分不出两代持有者**（`租约.mjs` 头部"★★ 1013 收口"）。⇒ 子代理 id **必须由父进程现摇并显式传**（`--窗 <子号>` 或 env），不许读引擎 env。
3. **Termux 二进制要补库路径**（`CONTEXT.md:22`）：`export LD_LIBRARY_PATH=$F/usr/lib`。

**不推荐"多窗并发"**：她的"窗"= 会话，多窗 = 多个独立注入面（上下文成本翻倍），且换窗要重走打烊/开窗（03 §4.3/§4.4）。推荐形态是 **单窗 + 多 node 子进程**（或单进程内 `Promise.all` 发多家 HTTP）。

**并发度**：外部核是**网络 I/O 绑定** ⇒ 5 家全并发无压力。若子代理跑本地 `.mjs`（CPU/IO 混合）⇒ **并发度 ≤3**；若同时有人在动 731MB 的 `index.db`（`CONTEXT.md:39`）⇒ 降到 2，且**禁止在并发期间跑 VACUUM/重建**（02 §4.1 明确 731MB 库重建是长事务）。

### 4.3 并发安全四道纪律（回答"会不会撞锁"）

她的 `_锁/` 目录（`锁.mjs`：`锁目录 = path.join(根,'_锁')`）**只在写共享件时才需要**。设计上让子代理**根本不碰共享件**，撞锁概率归零：

| # | 纪律 | 机制 |
|---|---|---|
| 1 | **子代理只写自己的槽** | 产物落 `_tmp/并行/<run>/<子号>.json`，文件名含父进程摇的子号 ⇒ **零写冲突，一把锁都不用** |
| 2 | **共享件只在合并阶段写，且只有主进程写** | 主进程单线程，走 `锁.mjs 原子写`（临时文件+fsync+rename） |
| 3 | **要改同一个"件" ⇒ 先拿意图级租约** | `租约.mjs 取 <件> --窗 <子号>`；拿不到 ⇒ 该子直接报"被占，换活"，**不许抢**（租约自带世代号，旧世代顶不掉新世代） |
| 4 | **真要写同一文件 ⇒ 动作级互斥** | `锁.mjs 带锁('队列-'+名, …)`；拿不到就抛（`带锁` 的语义就是"不硬干"），**不许降级成"先写着"** |

> 一句话：**意图级用租约（谁改这件事）、动作级用锁（谁在写这一下）、产物各写各的（根本不争）。** 她这两层锁已经分别存在（`租约.mjs:1-8` 明写"锁.mjs 是动作级毫秒互斥，租约补意图级"），只是没接到并发上。

### 4.5 最小实现：`工具/并行/并发核.mjs`（关键片段）

```js
#!/usr/bin/env node
// 并发核 —— 跨模型核.mjs 的并发改造（原 :88 是串行 for）
// 纪律：子写各槽 / 主写合并 / 意图用租约 / 动作用锁
import fs from 'node:fs'; import path from 'node:path'
import { 带锁, 原子写 } from '../../神经/锁.mjs'
const 出根 = '/storage/emulated/0/3/_tmp/并行'
const run = process.argv[2] || ('r' + Date.now().toString(36))
const 槽 = path.join(出根, run)
fs.mkdirSync(槽, { recursive: true })

const 摇子号 = i => `${run}-s${i}-${Math.random().toString(36).slice(2,6)}`  // ★ 父摇，不读 DSH_SESSION_ID

/** 发一家：带独立超时 + 契约校验，只写自己的槽 */
async function 发一家(key, 模型, 包, 子号, 秒=120) {
  const t0 = Date.now()
  let 原 = ''
  try {
    const r = await fetch('https://4sapi.org/v1/chat/completions', {
      method:'POST',
      headers:{ Authorization:'Bearer '+key, 'Content-Type':'application/json' },
      body: JSON.stringify({ model: 模型, messages:[{role:'user', content: 包}], max_tokens:3500 }),
      signal: AbortSignal.timeout(秒*1000)      // ★ 每家独立超时，一家慢不拖全队
    })
    原 = await r.text()
    const 答 = JSON.parse(原)?.choices?.[0]?.message?.content || ''
    const 卷 = 解契约(答)                        // 抽 ```json 块；解不出 = 无效卷
    return { 子号, 模型, 状态: 卷 ? 'ok' : '不成文', 秒: Math.round((Date.now()-t0)/1000), 卷 }
  } catch (e) {
    return { 子号, 模型, 状态: '失败', 秒: Math.round((Date.now()-t0)/1000), 因: e.name+' '+String(e.message).slice(0,120) }
  }
}

/** ★ 并发本体：一家慢不阻塞别家，一家失败不中断全队 */
const 结果 = await Promise.allSettled(
  名单.map((id, i) => 发一家(key, id, 包文本, 摇子号(i), 秒)
    .then(r => { fs.writeFileSync(path.join(槽, r.子号 + '.json'), JSON.stringify(r)); return r }))
)
const 卷 = 结果.filter(r => r.status==='fulfilled').map(r=>r.value)

/** ★ 合并是唯一写共享件的地方：主进程单线程 + 带锁 + 原子写 */
带锁('合并-'+run, () => {
  原子写(path.join(槽,'汇总.json'), JSON.stringify({
    run, 材料字数: 包文本.length, 时: new Date().toISOString(), 卷
  }, null, 1))
}, { 等毫秒: 8000 })

// 判卷见 §4.4 四条规则；无效卷/矛盾卷 → 台账/接续/待你决.md
```

**从 `跨模型核.mjs` 迁移时只改三处**：`for` → `Promise.allSettled`；`答卷_<模型>.md` → `<子号>.json`（契约）；末尾加 `判卷`。**材料准备那一套（模型池、`--重试`、降级顺序）一行不动。**

### 6.1 能不能用"角色化 prompt 模板 + 独立上下文"模拟会诊？

**能，而且比 WorkBuddy 更像真的会诊。** 理由：

- **"独立上下文"这一格她天然就有**：外部模型只收到那一份派活包，**不继承主窗上下文**。`派活.mjs` 头部注释就是这么写的："子代理／外部模型是 fresh 上下文，**不继承我每轮收到的记忆检索块**"。⇒ 不需要任何额外机制去"隔离上下文"。
- **"多专家"这一格她已经有 5 位**：`工具/跨窗/模型池.json` 里 Astra / Opus 5.5 / Sonnet 5.5 / GPT-5.5 / Gemini 3.1 Pro，**全部实测通**（2~4s）。

**但今天她把同一份材料发给 5 家 ⇒ 5 份同质答案。** 缺的正是"角色化"。

### 6.2 她现在是什么样 → 改成什么样

| | 现在 | v52 |
|---|---|---|
| 角色 | 无。5 家收到同一份材料 | `模型池.json` 每行加 `角色`；`工具/技能/角色库/<角色>.md` |
| 派活包 | 主题 + 相关坑原文 + 5 条铁律（`派活.mjs`） | **＋ 角色段 ＋ 输出契约（§4.4）** |
| 会诊 | 5 家各写各的，人读 | `判卷.mjs` 按 §4.4 四条规则判，矛盾并列进 `待你决` |
| 数量 | — | **8 个角色，每次挑 3 个** |

### 6.3 8 个角色（不要 100+）

```
角色库/
  架构.md    立场：先问"这个改动会牵动哪几处"（她的 五处同改核.mjs 就是这个角色）
  安全.md    立场：先看 key/权限/外发（CONTEXT.md:85 明文 key 第二次出现 ⇒ 这个角色有活干）
  成本.md    立场：先算字数/步数/钱（她的 单价.mjs / 上下文账.mjs）
  验收.md    立场：先问"判据是什么、反例是什么"（派活铁律 2 就是这个角色）
  反证.md    立场：只负责推翻，不负责建设
  记忆.md    立场：先问"这条我是不是已经犯过 / 这事裁过没"（动作集 B09 双查）
  连续性.md  立场：先问"下一窗接得住吗"（03 §4）
  老板口径.md 立场：先问"这是他亲口说的，还是系统注入的"（CONTEXT.md:79 / 03 §6）
```

每个角色 **≤600 字**，三段：立场 / 不许做什么 / 输出必须含什么。

**每次挑 3 个**（不是 8 个全发）：**架构 + 验收 + 反证** 是默认三件套；涉及 key/外发 ⇒ 换上 **安全**；涉及"这事是不是做过了" ⇒ 换上 **记忆**。

### 6.4 与"子代理并行"是同一件东西

**不要做两套。** 角色库只是 `派活.mjs` 的一个参数、并发核的一份输入：

```
派活.mjs <主题> --角色 架构,验收,反证 --词 …  →  台账/接续/派活/<戳>-<主题>.md
并发核.mjs run --包 <那份派活单>            →  _tmp/并行/<run>/<子号>.json × 3
判卷.mjs <run>                              →  采纳/驳回/补派 → 待你决.md
```

**⚠️ 一条硬边界**：外部模型**没有工具**（`派活.mjs` 对"千问"明写"禁止调用任何工具，直接凭材料推理"）⇒ 它们的结论**不可自证**。因此契约里 `证据[].引` 必须指向**我给的材料里的原文**，引用不到的判无效（§4.4 规则 2）。这条不写进去，会诊就变成"5 个模型一起编"。

## 8 · 机制七：skill 安装前安全审计（改造后移，第 8）

**她不需要新造这道门——引擎原生就有"真拦"的能力。**

```js
// vendor/dshmarketplace-plugin/lib/index.js:8（现成写法）
t.on("tools/pre-execute", async (t, n) => {
  ...
  t.requireApproval?.({ title: `Install ${e.name}?`, detail: [...风险清单, e.url] })
  return n()
})
```

**为什么这条关键**：`CONTEXT.md:77` 已确诊"119 门只有 8 处真拦；ENTER-GATE 是哑门（`if(hasCard)`）"。她的门之所以是摆设，是因为**门只是一段被注入的文本**——模型可以选择不看。

| | 现在 | v52 |
|---|---|---|
| 门的实现 | 注入文本 + 提示词（模型可以不看） | **`requireApproval` 拦截**（不看也得停下） |
| 装技能 | 无审计 | `装技能.mjs` 装前跑审计：① SKILL.md 里有没有 `真源` 路径 ② 真源在不在盘 ③ 正文里有没有 `rm -rf`/外发/`fetch` 到非白名单域名 ④ 有 ⇒ 走 `requireApproval` |

**纪律**：只把 **"会造成不可逆后果"** 的动作用 `requireApproval` 真拦（装包、删库、外发 key、改构建链）；**其余一律降级成"报出来但不拦"**——否则又会长成 119 门常红没人看的老样子（03 §11 R4 同口径："一上来就硬拦 ⇒ 常红 ⇒ 没人再看"）。

## 10 · 风险与待验证

### 10.1 最大风险

> **R1 · 技能装机位 `$B/skills/` 不在构建链 ⇒ 下一版重新打包后技能全丢，回到"在跑旧货"。**

这不是假设：01 §1.2 已确证 **`@dsh-user` 用户插件层（19 个目录 / 6.3 MB）在本地源码树里一个都没有**，且 01 §5 判定"在跑旧货"的根因之一就是"用户插件不进构建链"。把 12~18 个技能装进 `$B/skills/` 若不做防护，**等于复制同一个病**。

**三道必须同时做**：
1. 真源在 sdcard（`工具/技能/`），`$B/skills/` 永远是可再生成物
2. `装技能.mjs` 挂开窗（必然时刻），开机必校验 sha
3. 技能清单 sha256 进 01 §5 的启动漂移自检（与 buildId 同张报表）

> **R2 · 并发期间动 731MB 的 `index.db`。** `CONTEXT.md:39` 记它 731,205,632 字节且最后写 10-26。02 §4.1 明确不 VACUUM 而重建。并发扇出期间**禁止**跑重建/建库 —— 长事务 + 多读者 ⇒ 锁表或 OOM。⇒ `并发核.mjs` 起跑前先查 `_锁/` 里有没有 `建库/重建` 的锁，有就排队。

> **R3 · 子代理身份退化。** `DSH_SESSION_ID` 在引擎进程读不到（租约.mjs 头部）⇒ 若子号靠读 env，所有子代理会拿到同一个 id ⇒ 租约/锁的世代号失效 ⇒ 复现 1013 那个"过期持有者顶掉现役"的病。**必须父摇子号并显式传。**

> **R4 · 外部会诊变成"5 个模型一起编"。** 外部模型无工具、不继承上下文 ⇒ 若契约里不强制"引用我给的材料原文"，答案会看着很专业但全是编的。⇒ §4.4 规则 2 是硬判据，不是建议。

> **R5 · 移植本身制造新的孤儿件。** 她已有 12 个一级目录、20 内核件、173/295 覆盖率。每新增一件必须带 `出口账` 三字段（消费方/复核周期/退休条件，`出口账.mjs:47`），**没有消费方的件不许上车**——这正是 §5 要解决的病。
