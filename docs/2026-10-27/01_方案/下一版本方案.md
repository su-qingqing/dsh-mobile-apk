# v52 总方案 · 平板 DSH Harness 下一版本

> 六位专家分头调研后的合并裁决。**本文档是开工依据**，细节在 `plan/experts/01~06`。
> 证据口径：真机 v51（versionCode 51 / 0.14.7-rc2main2）＋ 332 窗精读 ＋ 最近一周 42 窗精读 ＋ 设备实测。
> 调研全程**只读**，未改动平板与源码树。

## 〇、先说三件推翻原判断的事

| 原以为 | 实测 | 影响 |
|---|---|---|
| 本地副本 v38 是 v51 的源码，残缺 75 个文件 | v38 是 **2026-09-15 的旧分支**；真机 v51 = 上游 `v0.14.7`，而 **`v0.14.8` 就是 versionCode 52**。那 75 个"删除"**全在 `.git` 对象库里**，`git restore` 即可 100% 恢复 | **不能在 v38 上补 13 个版本**。基线改为克隆 `v0.14.8` 新树 |
| `.dsh/state/跨窗/index.db` 是跨窗交接库 | 731MB 是**会话全文检索库**（336 窗/12.7 万条，8 表只有 meta+raw+FTS 影子表）。交接所需的针/卡/在办**一张表都没有** | 交接库要从零建；731MB 属异常膨胀（89% 的行已删但从不 VACUUM） |
| "在跑旧货"是插件缺 `inject` | `inject` 是 UI 注入声明，kickoff-gate 本就不该有。真因是**四方漂移**：装配清单双真源（仓库 16,998B vs 真机 63,056B）＋ `@dsh-user` 19 个插件**不在构建链** | 修 inject 修不好；要修的是构建链与启动自检 |

## 二、交叉风险（只有汇总时才看得见，这是本方案最关键的一节）

### ⚠ 风险 A：新能力计费会引爆硬停闸，重演"系统自伤"
04 号测出做图 ¥0.16/张、建模 ¥2.1–4.2/件，**远超她 ¥0.05/步的步账上限**；
06 号测出「上一轮未结红」硬停闸会**关掉整个工具面**，她无法自救（已复现 2 次，`6e40704b`）。
→ **两个独立方案一叠加，就是"新功能一用 → 未结红 → 工具面全关 → 她瘫了"**。
**对策**：多模态上线**必须同时**做三件事——单列"件账"、件账与步账分离、硬熔断改成降级而非停摆。顺序上，06 的"最小可用工具面"必须先于 04 上线。

### ⚠ 风险 B：瘦身前必须先做实"取回"
03 号自己警告：削常驻（−24,041 字/轮摘要、−6.3 万字符/轮工具定义）前，若 `hitTopK` 仍是 2、负知识必查没接上，**会比现在更空**——她原文写过"落'可丢'＝指针在场、内容照样不在场"。
**对策**：并帐 + 负知识必查做完并通过验收，**才许动瘦身那两刀**。

### ⚠ 风险 C：覆盖安装可能让她 4.6GB home 归零
01 号最大风险：731MB 跨窗库 + 19 个用户插件 + 4.6GB home，覆盖安装能否 100% 保留**未经验证**。
**对策**：先在备份路径/副机验证，再动现役机。备份未完成不许装。

### ⚠ 风险 D：照搬平台机制会复制"跑旧货"同一个病
05 号测出 `$B/skills` **不在构建链**（正是"在跑旧货"根因之一）。若把 WorkBuddy 的 Skills 机制照搬进去，等于复制同一个病。
**对策**：真源放 sdcard + 装技能挂开窗 + sha256 进启动漂移自检。

### ⚠ 风险 E：明文密钥已两次泄露，新能力会第三次
`sk-u2nq…` 已两次明文出现在会话（含窗口标题），现在还躺在 `~/.dsh/.credentials.yaml`。多模态要接付费 API。
**对策**：密钥三层管理（详见 04 §5.2）＋**轮换密钥**先于多模态上线。

## 三、分阶段路线图（按依赖排序，不许乱序）

### P0 · 止血与备份（先做，否则后面一切白做）
1. **全量备份** home（4.6GB）＋ 跨窗库 ＋ 19 个用户插件 → 电脑侧留档，校验可恢复
2. **轮换 API key**，清 `~/.dsh/.credentials.yaml` 明文，清含 key 的窗口标题
3. **A08 硬停闸"留面"改造**（06）：被拦时至少能看红、能自救、能上报
   - ⚠ 06 实测：A08 已从现役 `工具/流程/表.mjs` **静默消失**（现役 2 条硬停 vs 1020 备份 3 条），而 `未结红.json` 现在就有红、处理=null
   - 验收：人为造一个未结红，验证她仍可看红、可自救、可上报
4. **"最小可用工具面"原则落地** —— 这是风险 A 的前置

### P1 · 打通生效链路（不打通，后面所有改动都是白改）
1. 克隆 `v0.14.8` 到**新工作树**（不动 v38）；`git restore` 恢复那 75 个文件
2. 取官方快照 `snapshot-arm64.tar.xz` 放进 `app/src/main/assets/`
   - ⚠ 这是**唯一硬阻断**：`app/build.gradle.kts:93-105` 会因缺快照抛异常（dry-run 掩盖了它）
   - sha256 校验 `80801a23…` == 真机 `.snapshot-fingerprint` ✅
3. tar 回灌真机 `@dsh-user`（19 个/6.3MB）＋ 内核资产（148KB）
4. 17 处注册段评审后追加进权威 patch（**不许整段覆盖**，会抹掉 1011/1012/1014 修复）
5. 加 5 道机制保证"改了必生效"：构建号内嵌 / 插件清单 md5 / 启动漂移自检 / skills 进构建链 / 门禁扩到 `@dsh-user`
6. `build.bat` 出 debug APK → **先在备份环境验证 `install -r` 不丢数据** → 再上现役机

### P2 · 连续性与上下文（核心诉求）
1. **建跨窗交接库**（02 §3.3 有可直接执行的建表 SQL）
   - 核心：把"在办"建成唯一真源 `doing` 表（带 ball/TTL/陈旧天），三种文件降级为只读渲染
   - 针、卡、卡行、窗各自落表，卡行带 `expires_at` 与 `src_needle` 可追到针
   - ⚠ **三套口径（状态行 goal-54577121 / 交接单 045 / 在办.md）必须三条并列进表交老板裁，脚本不许自动合并**
2. **收编孤儿件**：`抽针.mjs`/`出卡.mjs` 全工作区**零调用方**，`打烊规程.md` grep「针/出卡」**全 0 命中** → 接进打烊工序
3. **负知识接检索口**（03 §5）：73 条从"素材"变"火线"，动手前机器挂载必查 —— **这是 P2 瘦身的前置**
4. **上下文预算重分**：常驻 6 万 / 召回 4 万 / 工作区 46 万 / 思考 10 万 / 安全垫 14 万；水位线把老板"七八成该停"翻成机器数
5. **来源戳 + TTL**（治"分不清老板话 vs 注入"、`e6954dac` 白跑 30 步）
6. 731MB 老库**不 VACUUM，直接重建**，检索库另开文件、可丢弃

### P3 · 能力扩展
1. **平台移植**（05）：三层记忆 → Skills 按需加载（引擎**原生就有** `skills.register`，她只装了 2 个）→ 子代理并行（她已攒齐 5 个零件，只差并发/契约/审核三道）
   - 明确**不移植** automation：Android 无常驻、Termux 无 cron，到点跑不起来会长成第 120 个"门是摆设"；改事件触发
2. **多模态**（04）：做图走 4sapi（**强制 `response_format=b64_json`**，图托管在 imgen.x.ai 大陆直连超时）；3D 走百炼 Tripo（¥2.1–4.2/件，异步，RPM=5）
   - 前置：P0 密钥轮换 + P0 硬停闸改造 + **件账单列与熔断**
   - 端侧只做：程序化建模（纯 node 直出 glTF）、GLB 后处理、2D 合成（`@napi-rs/canvas` 她已装）
3. **门治理**（06）：119 门 → 留 **8 道真门**（A01 开工卡 / A02–A04 收手门 / A05 取＝动作 / A06–A08 硬停），18 道 accept 类挪进"口子"，78 台改称"校验器"
   - **出题契约**：门不许只说"不许"，拦住时必须交出「缺什么 → 去哪补（一条可抄的命令）→ 补完怎么验 → 验不过找谁 → 这一步本身不被本门拦」

### P4 · 验收
可跑的自检：门禁体检（真拦 vs 哑门）、负知识必查率、换窗接得住率、上下文水位、件账熔断、构建漂移自检。
**唯一硬指标**：最近一周"没做成"比例 **45% → 显著下降**；同坑不复犯（NK-006 不许第四次）。

## 四、顺序硬约束（违反会出事）

1. **备份未完成 → 不许装 v52**（风险 C）

5. **硬停闸留面改造 → 先于多模态上线**（风险 A）
6. **skills 进构建链 → 才许移植 Skills 机制**（风险 D）
