## 四、handoverai 源码抽出来的东西（直接补 02 号交接库）

业界这家是跨窗交接调研里**唯一没验的一家**，现在验了。它的 `icl-handover-2.0.json` 顶层 9 个必填字段：

```
version / task / writer / budget / environment_scope / S_exact / S_stat / S_residual / integrity
```

`HandoverRecord` 上四个方法对 v52 直接有用：

| 方法 | 作用 | 对 v52 交接库的建议 |
|---|---|---|
| `seal(prior_record_hash)` | 每跳把**上一跳的哈希**封进本跳 | `card` 表加 `prior_hash` 列 → 交接链断了能立刻发现是哪一跳丢的 |
| `payload_hash_matches()` | 校验本跳内容没被改 | 加 `payload_hash` 列 → 零损失区（30条 E 组）不再靠"信任"，靠校验 |
| `hop_index()` | 第几跳 | 加 `hop` 列 → 一条事跨了多少窗有读数，不用猜 |
| `S_exact / S_stat / S_residual` 三段分治 | 精确段／统计段／残段分开存 | 对应我们「原文不进库（指针）＋统计可算＋残段保留」的分法，**思路对得上** |

→ 建议 `doing`/`card` 表**加 3 列**：`prior_hash`、`payload_hash`、`hop`。这是从已验证的业界实现里抄的，不是我拍脑袋。
