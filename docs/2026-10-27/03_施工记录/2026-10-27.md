## 16:05 构建事故：我把 31G 机器打爆了（老板追问「你干了什么直接内存溢出」）

**现象**：Gradle 构建中途 JVM native OOM，连 Git Bash 创建子进程都失败（`0xC0000142`）。
两份崩溃日志：`hs_err_pid8628`（Gradle daemon 4G 堆，`mmap 164MB for G1 virtual space` 失败）、`hs_err_pid16652`（1MB `malloc` 失败）。

**根因（全是我的操作）**：
1. 照搬仓库 `gradle.properties` 的 `-Xmx4g` + `parallel=true`，16 核并行全铺开
2. 构建进行中执行 `gradlew --stop` → 留半死 daemon
3. 换 `--no-daemon` 但**没关 Kotlin 独立 daemon**（约 1.7GB，且不随 --no-daemon 退出）
4. 失败后 15:32→15:52 连续重启 4 次，JVM 孤儿叠加（清理时仍有 PID 18140/1685MB 在跑）
5. 同期还挂着 adb 4.8GB tar 流 + git clone + 156MB 下载

**判据（以后先看这个再动手）**：Windows 的 `Memory Compression` 进程占 9.2GB = 已经在硬扛内存压力，此时任何 4G 堆的 JVM 都会把系统打穿。

**修好的配方（已验证 BUILD SUCCESSFUL）**：
```
--no-daemon --max-workers=2
-Dorg.gradle.parallel=false
"-Dorg.gradle.jvmargs=-Xmx3g -XX:MaxMetaspaceSize=512m -Dfile.encoding=UTF-8"
-Pkotlin.compiler.execution.strategy=in-process     # ← 最关键，干掉独立 Kotlin daemon JVM
```
峰值后 free 仍有 7.6GB。**不许再连续重启构建**，失败先读 hs_err 再动。

**另一个坑**：`.bat` 文件必须 ASCII + CRLF。Write 工具只写 LF，导致 `-Dorg.gradle.parallel=false` 被解析成 `'rallel' 不是内部或外部命令`。用 `sed -i 's/$/\r/'` 转换。
