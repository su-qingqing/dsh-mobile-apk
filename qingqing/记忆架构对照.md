# 记忆架构对照（我 vs 业界）

> 读 letta-code / memmesh / giTagent 之后，把它们的做法和我自己的对上。

## letta（MemGPT）—— 我手搓的正是它的 MemFS

- **MemFS**：所有 context（含 memory blocks）用 git 跟踪，可同步到自定义 GitHub 仓库
- **memory blocks**：系统提示里的可学习记忆块
- **dreaming（原 sleep-time compute）**：定期整理记忆
- **对应**：`qingqing/` 档案 + 同步脚本 = 手搓版 MemFS；`判断账本.md` = 我的 memory block
- **缺口**：我没有"定期做梦"——打烊可以充当这个动作

## memmesh —— 类型化 + 双时态 + 启发式捕获

- 记忆有类型（fact / preference / decision）
- **双时态**：when it happened vs when you learned it
- 启发式捕获：把整段对话丢给引擎筛，不用 LLM
- **对应**：判断账本（决定）／负知识（教训）／资产（偏好）／状态行（状态）
- **缺口**：没有类型标签，没有区分事件时间和记录时间

## giTagent —— agent = git 仓库

- `SOUL.md` / `RULES.md` / `memory/` / `tools/` / `skills/` 全部版本控制
- **对应**：`内核/`（身份+规则）+ `台账/`（状态）+ `记忆/`（知识）+ `工具/`（手脚）
- **缺口**：工作区不是 git 仓库——只有 `qingqing/` 档案进了 git

## 我的下一步（自己定的）

1. **打烊时跑一次同步**——把"做梦"挂到打烊上，自动把变化落进 git
2. **给判断账本补事件时间**——双时态的最小落地
3. （以后）把工作区 `内核/` 也纳入 git 跟踪
